第 6 章 · Part 2：安裝與快速上手

Web UI 視覺化探索

把知識圖譜變成可互動的視覺化介面——Bridge 模式、WASM 模式與圖譜探索全攻略

兩種進入 Web UI 的路徑

模式 入口 資料來源 repo 大小上限 需要安裝？
Bridge 模式 gitnexus serve → 瀏覽器開啟 本地 CLI 索引的 LadybugDB（native） 無限制（後端在本地） 需要（全局安裝 gitnexus）
WASM 模式 gitnexus.vercel.app，拖入 ZIP 或貼 URL 瀏覽器內 Tree-sitter WASM 現場解析 ~5,000 個檔案 不需要

Bridge 模式：大型 Repo 本地視覺化

先完成 gitnexus analyze 索引，再執行：

啟動 Bridge 模式 
# 啟動 Bridge 模式（本地 HTTP 後端，Port 4747）
gitnexus serve

# 輸出示例：
# 🚀 GitNexus server running at http://localhost:4747
# Serving repo: /Users/porter/projects/my-app
# Open https://gitnexus.vercel.app to connect

執行後 GitNexus 啟動一個 HTTP 伺服器在 Port 4747，Web UI（gitnexus.vercel.app）會自動偵測 localhost:4747 並連上。你在瀏覽器看到的圖譜資料，完全來自本地 .gitnexus/db/ 裡的 LadybugDB——不上傳任何東西到伺服器。

gitnexus serve 選項 
# 指定 repo 路徑（預設為當前目錄）
gitnexus serve /path/to/my-repo

# 指定不同 port（預設 4747）
gitnexus serve --port 8080

# 不自動開啟瀏覽器
gitnexus serve --no-open
💡
為什麼要 Bridge 模式而不是直接用 WASM 模式？

WASM 模式在瀏覽器裡現場解析，受限於瀏覽器記憶體（約 5,000 個檔案）。Bridge 模式則讓 Web UI 作為 frontend，呼叫本地 gitnexus serve 的 HTTP API 取得已建好的 LadybugDB 圖譜資料，突破記憶體限制，適合大型商業 repo。

WASM 模式：免安裝快速探索

打開 gitnexus.vercel.app，無需任何安裝，直接丟入你想探索的程式碼庫：

WASM 模式輸入方式 
# WASM 模式不需要任何本地服務
# 直接拖入 ZIP 或貼 GitHub URL：

支援的輸入方式：
  1. 拖入 ZIP 檔案  →  瀏覽器解壓 + 本地解析
  2. 貼上 GitHub URL → 自動抓取並解析（需要網路）
  3. 本地 Bridge 模式 → 自動偵測 localhost:4747

WASM 模式的完整解析流程在瀏覽器內執行：Tree-sitter WASM 解析 AST、LadybugDB WASM 建圖、向量索引建立。關閉分頁後資料消失，下次再來需要重新載入——這是 WASM 模式的取捨，換來的是零安裝的便利。

ℹ️
GitHub URL 輸入

貼上任何公開 GitHub repo 的 URL（如 https://github.com/facebook/react），Web UI 會自動下載並解析。適合快速探索開源專案架構，不需要先 clone 到本地。

左側面板：Clusters 與 Processes

左側面板列出 Leiden 演算法自動偵測出的所有功能集群（Clusters）與執行流程（Processes）：

  • 點擊 Cluster：畫布過濾，只顯示屬於該集群的節點及其邊
  • 點擊 Process：高亮顯示完整執行路徑，從入口點到終點的所有節點與連線
  • 搜尋篩選：左側面板頂部有搜尋框，可快速過濾集群與流程名稱

使用搜尋功能

頂部搜尋框支援混合搜尋（BM25 + 語義向量 + RRF），不只是字串比對：

搜尋示例 
# 在 Web UI 的搜尋框輸入，等效 MCP query 工具

semantic search 示例：
  "handle user authentication"
  "payment processing logic"
  "rate limiting middleware"

keyword search 示例：
  "validateToken"
  "UserService"
  "prisma.user.findUnique"
💡
語義搜尋需要 --embeddings

如果你在 CLI 端執行索引時沒有加 --embeddings 旗標，Web UI 的搜尋只有 BM25 關鍵字搜尋，無法用「handle user authentication」這種語義描述搜尋。建議執行 gitnexus analyze --embeddings 重建索引後再進入 Web UI。

Graph RAG 對話功能

Web UI 內建 Graph RAG 模式，讓你能用自然語言直接與 codebase「對話」，類似 ChatGPT 問答，但底層查詢的是知識圖譜而非純向量：

  • 切換到 Chat 標籤頁，輸入問題如「這個 repo 的認證流程是怎麼運作的？」
  • Graph RAG Agent 會先用 query + context 工具定位相關節點，再用 LLM 合成回答
  • 回答中的程式碼引用可以點擊跳轉到圖譜中的對應節點
ℹ️
Graph RAG vs 直接使用 MCP 工具

Graph RAG 對話的底層也是 MCP 工具（query、context、impact）的組合呼叫。差別在於：Web UI 的 Graph RAG 是在 Web 端呼叫，中間有 LLM 推論費用；而透過 Claude Code 的 MCP 整合，等同你在 Claude Code 會話中直接呼叫這些工具，效率更高，也整合到你的開發工作流中。Web UI 的 Graph RAG 更適合快速探索、演示，不適合日常開發整合。

常見 Web UI 問題

問題 可能原因 解決方式
Bridge 模式顯示「無法連接 localhost:4747」 gitnexus serve 未執行，或 Port 被佔用 確認 gitnexus serve 已執行；檢查 Port 4747 是否衝突
WASM 模式載入後圖譜空白 repo 解析中，或超過 5,000 檔案上限 等待載入完成；大型 repo 改用 Bridge 模式
搜尋語義不準確 索引時未加 --embeddings 重新執行 gitnexus analyze --embeddings
Windows 防火牆阻擋 Bridge 連線 Windows 防火牆封鎖 Port 4747 在 Windows 防火牆允許 Port 4747 的入站連線；或改用 127.0.0.1 而非 localhost

小結：Web UI 的最佳使用時機

  • 新進成員 onboarding：視覺化看整個 repo 的架構，快速理解各模組職責
  • 架構討論：截圖某個集群或執行流程的圖譜，在設計評審中說明影響範圍
  • 探索陌生開源專案：貼 GitHub URL 到 WASM 模式，免 clone 快速摸清架構
  • Demo 展示：向客戶或主管展示 GitNexus 的視覺化能力
