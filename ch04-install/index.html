第 4 章 · Part 2：安裝與快速上手

安裝與環境設定

一行 npm 指令開始，三種使用模式任你選

前置需求

GitNexus 是 Node.js 工具，安裝前確認以下環境：

依賴 最低版本 說明 下載
Node.js 18+（建議 LTS） GitNexus 必需的執行環境 nodejs.org
npm 8+ Node.js 安裝時一起附帶 —
Git 任意版本 部分依賴拉取需要；detect_changes 功能需要 git-scm.com

安裝前先驗證環境：

驗證前置環境 
# 驗證前置環境（在終端機執行）
node -v      # 需要 v18 以上
npm -v       # 需要 v8 以上
git --version
💡
Windows 安裝 Node.js 記得勾選「Add to PATH」

從官網下載 Node.js 安裝程式時，安裝步驟中務必勾選「Automatically install the necessary tools」以及「Add to PATH」，否則後續執行 npm 指令時可能提示找不到命令。

全局安裝 GitNexus

安裝 GitNexus 
# 標準安裝（推薦）
npm install -g gitnexus

# Windows 常見的依賴衝突問題備案
npm install -g gitnexus --legacy-peer-deps

# npm 11.x 用戶備案（npx 有 arborist bug）
pnpm --allow-build=@ladybugdb/core --allow-build=gitnexus --allow-build=tree-sitter dlx gitnexus@latest analyze

# 跳過 optional grammar 編譯（無 C++ 工具鏈時用）
# 跳過後 Dart/Proto/Swift/Kotlin 解析不可用，其餘語言不受影響
set GITNEXUS_SKIP_OPTIONAL_GRAMMARS=1
npm install -g gitnexus

等待安裝完成，終端輸出 added XXX packages in Xs 即表示安裝成功。

安裝驗證

驗證安裝 
# 確認安裝成功
gitnexus --version   # 輸出版本號（如 1.6.x）
gitnexus --help      # 查看可用指令

Windows 環境變數設定

在 Windows 安裝完成後，如果執行 gitnexus --version 出現「無法識別命令」，需要手動將 npm 全局安裝路徑加入環境變數：

Windows 環境變數設定 
# 取得 npm 全局安裝路徑
npm config get prefix
# 輸出示例：C:Users你的用戶名AppDataRoaming
pm

# 將此路徑加入 Windows 環境變數 Path：
# 1. Win+R → 輸入 sysdm.cpl → 進階 → 環境變數
# 2. 在「用戶變數」的 Path 中新增上面取得的路徑
# 3. 確定 → 重新開啟終端機

三種使用模式

GitNexus 提供三條入口，根據你的使用場景選擇：

三種模式快速對比 
使用模式對比：

CLI + MCP（日常開發推薦）      Web UI（快速探索）
────────────────────────────   ──────────────────────
npm install -g gitnexus        免安裝
gitnexus analyze               拖入 ZIP 或貼 GitHub URL
gitnexus setup                 gitnexus.vercel.app
無 repo 大小限制                ~5,000 檔案（瀏覽器記憶體）
LadybugDB native（持久化）      LadybugDB WASM（session 內）
Docker 可自托管                 Bridge 模式連本地 backend
模式 適合場景 安裝方式 repo 大小
CLI + MCP 日常開發，深度整合 Claude Code / Cursor / Codex npm install -g gitnexus 無限制
Web UI 快速探索、Demo、一次性分析；免安裝 gitnexus.vercel.app（拖入 ZIP 或貼 URL） ~5,000 檔案
Docker 團隊共用、CI/CD 流水線、內網部署 docker compose up -d 無限制
ℹ️
Bridge 模式：Web UI + CLI 後端

執行 gitnexus serve 啟動本地 HTTP 伺服器（Port 4747），Web UI（gitnexus.vercel.app）會自動偵測並連上，讓你在瀏覽器視覺化介面中使用 CLI 索引的完整大型 repo，突破 5,000 個檔案的瀏覽器記憶體限制。

常見安裝問題排查

問題 可能原因 解決方式
安裝超時 / 失敗 npm 版本衝突或網路問題 加上 --legacy-peer-deps 重試；或改用 pnpm
gitnexus: command not found npm 全局 bin 目錄不在 PATH 中 執行 npm config get prefix 取得路徑並加入環境變數
C++ 編譯錯誤（tree-sitter-kotlin 等） 無 C++ 工具鏈（python3/make/g++） 設 GITNEXUS_SKIP_OPTIONAL_GRAMMARS=1 跳過選用語法，或安裝 VS Build Tools
npm 11.x arborist bug npm 11.x 的 npx 有已知 bug 改用 npm install -g gitnexus 全局安裝，或改用 pnpm
Port 4747 被佔用 其他程序已佔用該 port Windows：netstat -ano | findstr :4747 找到 PID 後結束程序

安裝後的下一步

安裝驗證成功後，進入你的專案目錄，執行第一次索引：

步驟 指令 說明
1. 索引程式碼庫 npx gitnexus analyze 在 repo 根目錄執行，建立知識圖譜
2. 設定 MCP（一次性） npx gitnexus setup 自動偵測編輯器，寫入 MCP 配置
3. 啟動 Web UI（可選） gitnexus serve Port 4747，搭配瀏覽器視覺化探索

第 5 章會詳細說明 gitnexus analyze 的各個參數與索引策略。

💡
推薦：全局安裝 + gitnexus setup

相較於每次用 npx gitnexus@latest，全局安裝後直接執行 gitnexus setup 會寫入絕對路徑的 MCP 配置，啟動更快，不受 npx 冷啟動時間影響（否則可能超過 Claude Code 的 MCP_TIMEOUT 預設值約 30 秒）。
