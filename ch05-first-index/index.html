第 5 章 · Part 2：安裝與快速上手

索引你的第一個程式碼庫

gitnexus analyze：零 Token 消耗，本地完成所有計算

第一步：執行索引

確認已在 repo 根目錄後，執行：

執行基礎索引 
# 在 repo 根目錄執行（必須是真正包含程式碼的目錄）
npx gitnexus analyze

# 或全局安裝後直接執行
gitnexus analyze

GitNexus 會掃描所有程式碼檔案、用 Tree-sitter 解析 AST、解析跨檔案依賴、偵測功能集群、追蹤執行流程，最後建立搜尋索引。全程在本地執行，不消耗任何 LLM Token。

幾個關鍵數字：

  • Symbols：被解析出的函式、類別、方法、變數等符號總數
  • Relations：符號間的關係數（呼叫、匯入、繼承、參考）
  • Clusters：Leiden 演算法自動分組出的功能集群數量
  • Processes：從入口點追蹤出的完整執行流程數量

重要參數詳解

gitnexus analyze 參數一覽 
# 參數說明

gitnexus analyze                    # 基礎索引（無語義搜尋）
gitnexus analyze --embeddings       # 開啟語義向量（啟用 semantic search）
gitnexus analyze --skills           # 生成專案專屬 Agent Skills
gitnexus analyze --force            # 強制全量重建（忽略 stale 檢測）
gitnexus analyze --skip-embeddings  # 明確跳過向量，加速索引
gitnexus analyze --skip-git         # 非 Git repo 時跳過 git 相關操作
gitnexus analyze --verbose          # 詳細輸出，可看到每個階段耗時
gitnexus analyze src/components     # 只索引指定子目錄
參數 作用 額外耗時 建議
（無） 結構索引（呼叫圖、依賴、集群、執行流） — 首次嘗試用這個
--embeddings 額外建立語義向量索引，啟用自然語言搜尋 中等（HuggingFace 本地推論） 日常開發推薦加上
--skills 生成專案專屬的 4 個 Agent Skills 少量 完整整合時加上
--force 強制全量重建，忽略 stale 檢測 同首次索引 索引疑似損壞時用
--skip-embeddings 明確跳過向量，只做結構索引 節省向量計算時間 只需結構查詢時用
--skip-git 跳過 git 相關操作 — 非 Git repo 時用
--verbose 顯示每個階段的詳細耗時 — 排查索引問題時用
💡
--embeddings 的真正意義

不加 --embeddings 時，query 工具只有 BM25 關鍵字搜尋，無法用「找到處理用戶認證的程式碼」這種語義描述搜尋。加上之後，GitNexus 在本地執行 HuggingFace transformers.js 模型，把每個符號的語義也編碼進去——不需要 OpenAI API key，不需要網路，完全本地推論。

三種索引策略

三種索引配置 
# 基礎索引（快速，無語義搜尋）
gitnexus analyze
# 適合：首次嘗試、小型專案、只需結構查詢

# 推薦索引（結構 + 語義）
gitnexus analyze --embeddings
# 適合：日常開發、需要自然語言搜尋

# 完整索引（結構 + 語義 + Skills）
gitnexus analyze --embeddings --skills
# 適合：大型專案、完整 AI Agent 整合

.gitnexus 資料夾結構

索引完成後，repo 根目錄會出現 .gitnexus/ 資料夾，全局 ~/.gitnexus/ 會記錄 registry：

.gitnexus 資料夾結構 
.gitnexus/               ← repo 根目錄下，git 自動忽略
  db/                  ← LadybugDB 圖資料庫
    graph.db           ← 主圖譜（節點與關係）
    vectors.db         ← 語義向量索引（--embeddings 時建立）
  skills/              ← 生成的 Agent Skills（--skills 時建立）
    exploring.md
    debugging.md
    impact-analysis.md
    refactoring.md

~/.gitnexus/
  registry.json        ← 全局 repo 登錄（多 repo 管理）
ℹ️
.gitnexus/ 不需要提交到 git

GitNexus 執行 analyze 時會自動把 .gitnexus/ 加入 .gitignore。圖譜資料是本地計算的產物，不需要版本控制；任何人 clone 你的 repo 後，自己執行 gitnexus analyze 即可重建。

增量索引與 Stale 偵測

GitNexus 會追蹤自上次索引以來的檔案變更，再次執行 gitnexus analyze 時只重新解析變更的檔案，大幅縮短更新時間：

查看索引狀態與更新 
gitnexus status    # 查看當前 repo 的索引狀態
# 輸出示例：
#   Index: current (last updated: 2m ago)
#   Files: 1,247 indexed
#   Symbols: 81,400
#   Stale: No

gitnexus list      # 列出所有已索引的 repo（全局 registry）
情境 建議動作 說明
日常開發後更新索引 gitnexus analyze 增量更新，只處理變更檔案
大型重構後 gitnexus analyze --force 強制全量重建，確保圖譜一致性
切換到不同 branch gitnexus analyze 自動偵測 branch 差異，增量更新
PostToolUse Hook（Claude Code） 自動觸發 git commit 後自動提示重新索引，圖譜始終最新
💡
零 Token 消耗的本地計算

整個索引流程——Tree-sitter 解析、跨檔案依賴解析、Leiden 社群偵測、執行流程追蹤，甚至 --embeddings 的語義向量（HuggingFace transformers.js）——全部在你的機器上本地執行，不需要任何 API key，不消耗任何雲端 LLM Token。GitNexus 的「零伺服器（Zero-Server）」架構讓你的程式碼不離開本機。

索引完成後的下一步

索引成功後，你有兩個方向可以繼續：

  • 視覺化探索：執行 gitnexus serve，用瀏覽器看知識圖譜（第 6 章）
  • 接入 AI 編輯器：執行 gitnexus setup 設定 MCP，讓 Claude Code / Cursor 直接使用圖譜（第 10 章）
