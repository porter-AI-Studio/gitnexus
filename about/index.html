創作哲學

在 AI 浪潮席捲技術世界的此刻，Porter 是那種手握鍵盤、口述想法、讓 AI 奮筆疾書的協同作家——

他的工作流從不起頭於空白的編輯器，而是始於一句對話：「幫我分析修改這個函式的影響範圍。」幾輪工具呼叫後，完整的依賴圖已然成形；他的職責，是用三十年的工程判斷力，為 AI 的每一個輸出打上「可以」或「再想想」的印章。

這，就是他所定義的新時代工程師：不是寫所有程式碼的人，而是知道什麼程式碼值得被寫的人。

然而，在他對技術的熱情背後，藏著一份始終未曾褪去的人文關懷。他相信，真正偉大的系統從來不炫耀它有多複雜——它只是讓工廠工人的報表少看幾次、讓工程師的查詢從三十分鐘縮短到三秒、讓決策者在最需要的深夜，還能看見一盞清晰的數字明燈。

「工具越強大，越需要清晰的人文意志來駕馭它。技術是手段，人是目的——這是三十年來，我從未改變的設計信仰。」

為什麼寫這本 GitNexus 指南

使用 Claude Code 與各種 AI Coding Agent 的這幾年，Porter 深切體會到一個問題：AI 在單檔案的程式碼生成上已經非常出色，但在面對複雜的大型 codebase 時，它們仍然經常「盲改」——不知道改一個函式會波及多少地方，不知道依賴鏈在哪裡。

GitNexus 出現後，Porter 認為它是目前這個賽道上「最有機會真正解決結構盲點」的工具——零伺服器、本地優先、預計算關係，讓知識圖譜真正成為 AI Agent 的神經系統，而不只是一個漂亮的視覺化工具。

這本指南是他在深度使用 GitNexus 的過程中，整理出的系統化知識——從為什麼需要知識圖譜，到每一個 MCP 工具的實際使用場景，希望幫助每位使用 AI Coding Agent 的工程師，真正讓 AI 「看懂」你的程式碼庫。
