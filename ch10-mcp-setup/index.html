第 10 章 · Part 4：MCP 整合與 Agent 實戰

MCP 整合：連接 Claude Code 與各大編輯器

一行指令，讓你的 AI 編輯器擁有專案級上帝視角

快速路徑：gitnexus setup 自動配置

在完成索引後，執行一次 gitnexus setup，它會自動偵測你安裝了哪些 AI 編輯器，並寫入正確的 MCP 配置：

gitnexus setup 自動配置 
# 最快的方式：gitnexus setup 自動配置（一次性）
gitnexus setup

# 輸出示例：
# ✓ Detected: Claude Code
# ✓ Detected: Cursor
# ✓ Writing ~/.claude/claude_mcp_config.json ... done
# ✓ Writing ~/.cursor/mcp.json ... done
# ✓ Skills installed to .claude/skills/gitnexus/
# ✓ Hooks registered (PreToolUse + PostToolUse)
# Setup complete.

gitnexus setup 的工作內容：

  • 偵測已安裝的編輯器（Claude Code、Cursor、Codex、Windsurf、OpenCode、Antigravity）
  • 為每個編輯器寫入對應的 MCP 配置檔案（使用絕對路徑，不用 npx）
  • 為 Claude Code 和 Cursor 安裝 PreToolUse / PostToolUse Hooks
  • 為 Antigravity 寫入 AfterTool Hook 並安裝 skills
  • 把 repo 專屬 Skills 安裝到 .claude/skills/gitnexus/
💡
全局安裝 + gitnexus setup（強烈推薦）

gitnexus setup 寫入的 MCP 配置使用絕對路徑（"command": "gitnexus"），不走 npx。這樣 MCP Server 啟動時不需要 npm 下載，避免超過 Claude Code 的 MCP_TIMEOUT 預設值（約 30 秒）。相比之下，直接在 JSON 裡寫 npx -y gitnexus@latest mcp 在網路慢或快取失效時可能超時失敗。

各編輯器手動配置

如果偏好手動控制或 gitnexus setup 沒有正確偵測到你的編輯器，以下是每個編輯器的手動配置方式：

Claude Code

Claude Code：快速指令（推薦） 
# Claude Code 快速指令（macOS / Linux）
claude mcp add gitnexus -- npx -y gitnexus@latest mcp

# Windows
claude mcp add gitnexus -- cmd /c npx -y gitnexus@latest mcp

# 驗證 MCP 已加入
claude mcp list
Claude Code：JSON 配置（~/.claude/claude_mcp_config.json） 
// ~/.claude/claude_mcp_config.json（全局 MCP 配置）
// gitnexus setup 寫入的推薦格式（使用絕對路徑，避免 npx 冷啟動超時）
{
  "mcpServers": {
    "gitnexus": {
      "command": "gitnexus",
      "args": ["mcp"]
    }
  }
}

Cursor

Cursor：~/.cursor/mcp.json 
// ~/.cursor/mcp.json（Cursor 全局 MCP 配置）
{
  "mcpServers": {
    "gitnexus": {
      "command": "npx",
      "args": ["-y", "gitnexus@latest", "mcp"]
    }
  }
}

寫入後重啟 Cursor，在設定中確認 MCP 狀態為綠燈。Cursor 也需要手動安裝 PostToolUse Hook——見 GitHub 上 gitnexus-cursor-integration/README.md 的說明。

Antigravity（Google Gemini CLI）

Antigravity：~/.gemini/antigravity/mcp_config.json 
// ~/.gemini/antigravity/mcp_config.json（Antigravity MCP 配置）
{
  "mcpServers": {
    "gitnexus": {
      "command": "npx",
      "args": ["-y", "gitnexus@latest", "mcp"]
    }
  }
}

// gitnexus setup 也會同時在 ~/.gemini/settings.json
// 寫入 AfterTool Hook 並安裝 skills 到 ~/.gemini/antigravity/skills/

OpenCode

OpenCode：~/.config/opencode/config.json 
// ~/.config/opencode/config.json（OpenCode 配置）
{
  "mcp": {
    "gitnexus": {
      "type": "local",
      "command": ["gitnexus", "mcp"]
    }
  }
}

Codex

Codex：~/.codex/config.toml 
# ~/.codex/config.toml（Codex 系統級配置）
[mcp_servers.gitnexus]
command = "npx"
args = ["-y", "gitnexus@latest", "mcp"]

# 或 project 級 .codex/config.toml（只對當前 repo 生效）

各編輯器支援深度對比

編輯器 MCP 工具 Agent Skills Hooks 自動增強 支援等級
Claude Code ✅ 16 個 ✅ 4 個 Skills ✅ PreToolUse + PostToolUse 完整
Cursor ✅ 16 個 ✅ 4 個 Skills ✅ postToolUse（需手動安裝） 完整
Antigravity ✅ 16 個 ✅ ✅ AfterTool 完整
Codex ✅ 16 個 ✅ — MCP + Skills
Windsurf ✅ 16 個 — — MCP only
OpenCode ✅ 16 個 ✅ — MCP + Skills
ℹ️
Claude Code 的三重深度整合

Claude Code 享有最深度整合，因為它支援三層機制同時作用：

  • MCP 工具：16 個工具，隨時可直接呼叫
  • PreToolUse Hook：在 Claude Code 執行 Grep/Read/Write 等工具前，自動注入知識圖譜上下文，讓 Claude 在搜尋時就帶著圖譜視角
  • PostToolUse Hook：在 git commit/merge/rebase 成功後，自動偵測索引是否過時（stale），提示 Claude 重新執行 gitnexus analyze

連線驗證

驗證 MCP 連線 
# 驗證 MCP 連線是否正常
gitnexus list    # 應列出已索引的 repo

# 在 Claude Code 對話中驗證
# 直接問 Claude："use the gitnexus query tool to search for authentication logic"
# Claude 應能呼叫 gitnexus query 並返回結果

# 如果 MCP 連線有問題，查看 Claude Code MCP 狀態
claude mcp list   # 確認 gitnexus 狀態為 running

常見 MCP 連線問題

問題 原因 解決方式
MCP Server 啟動超時 npx 冷啟動時間超過 MCP_TIMEOUT（~30s） 改用全局安裝 + 絕對路徑："command": "gitnexus"
gitnexus 工具呼叫返回「no repos indexed」 當前目錄的 repo 還沒執行 gitnexus analyze 切到 repo 根目錄執行 gitnexus analyze
Claude Code 看不到 gitnexus 在 MCP 列表 配置檔案寫錯路徑或 JSON 格式錯誤 執行 claude mcp list 檢查；確認 JSON 無語法錯誤
Cursor 連線後無回應 Cursor 版本不支援或需要重啟 完全關閉並重新開啟 Cursor
Windows 找不到 gitnexus 命令 npm 全局 bin 目錄不在 PATH 中 執行 npm config get prefix 取得路徑，加入 Windows 環境變數（見第 4 章）

用 .gitnexusrc 固化專案配置

如果你有些 gitnexus analyze 選項每次都需要傳，可以在 repo 根目錄建立 .gitnexusrc 文件：

.gitnexusrc 配置範例 
// 在 repo 根目錄建立 .gitnexusrc 固化常用設定
// CLI flags 永遠優先於此檔案
{
  "defaultBranch": "develop",    // 預設分支（generate wiki/regression compare 用）
  "embeddings": true,            // 每次 analyze 都開啟語義向量
  "skipContextFiles": false,     // 不跳過 AGENTS.md/CLAUDE.md 生成
  "skipSkills": false,           // 不跳過 .claude/skills/gitnexus/ 安裝
  "workerTimeout": 60            // 大型 repo 的 worker timeout（秒）
}

注意：CLI 旗標永遠優先於 .gitnexusrc。這個檔案只是為了省去每次輸入相同旗標的麻煩，不是強制配置。

移除 MCP 配置

如果需要反向操作，gitnexus uninstall 可以安全移除所有 MCP 配置、Hooks 和 Skills：

gitnexus uninstall          # 預覽（dry run），列出會移除的路徑
gitnexus uninstall --force  # 實際執行移除

預設是 dry run（只預覽不執行），加 --force 才真正刪除。per-repo 索引（.gitnexus/）和 npm 套件本身（npm uninstall -g gitnexus）需要另外手動移除。
